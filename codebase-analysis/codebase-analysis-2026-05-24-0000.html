Open Issues, Bugs & Technical Debt

Dashboard shows placeholder study levels/countries HIGH

app/pages/3_Dashboard.py:22

The Dashboard calls db.fetch_students_df() which returns raw student table values. For ~1,800 students imported via bulk import, this shows study_level="Bachelors", country="Unknown" etc. Fix: change line 22 to db.fetch_full_students_df(). One-line change, no other impact.

importer.py is dead code that breaks on Postgres MEDIUM

app/importer.py (entire file)

The Import page UI was removed. No page imports or calls importer.py anymore. The file uses SQLite-specific conn.execute() directly and INSERT OR IGNORE syntax — it will fail silently or error on Postgres. The file and its tests (test_importer.py) should be deleted. The real bulk import tool is scripts/bulk_import.py.

build_quarterly_report alias passes empty enrich_df MEDIUM

app/report.py:build_quarterly_report()

The backward-compat alias build_quarterly_report(students_df, accomp_df, year, quarter) calls build_executive_report(students_df, accomp_df, pd.DataFrame()) — note the empty DataFrame for enrich_df. This means study duration and study level sections produce no charts/tables. Any caller using the old API gets a visually degraded report. Safe to remove once confirmed no callers remain.

updated_at column never updated LOW

app/database.py (students table schema)

The updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP column is set at insert time but never updated when records change. There is no edit UI yet, and no UPDATE query sets this field. Until an edit feature is added, this column is misleading — it shows the creation timestamp, not the last modification time.

PII committed to git repository HIGH (if repo goes public)

data_quality_report.xlsx (repo root)

The data quality report contains real student national IDs, full names, and birthdays. It was committed to demonstrate data quality issues to the source organisation. If this repo is ever made public or shared with external parties, this file must be removed from git history. For now (private repo), it is low risk but should be tracked. Add to .gitignore to prevent future versions being committed.

No student edit/update UI MEDIUM

Missing feature

There is no way to correct a student record via the web UI. Corrections require either: (a) delete + re-enter, or (b) direct SQL via Neon console. The students table has no UPDATE path in the app. This is the most common operational complaint from data-entry staff.

duplicate detection is O(n²) — will slow at scale LOW NOW

app/duplicates.py:flag_soft_duplicates()

The soft duplicate scan is a self-join: FROM students a JOIN students b ON b.id > a.id. This runs after every insert. At 1,822 rows it takes ~50ms. At 100,000 rows it would take ~50 seconds and would time out in Streamlit. When the table grows past ~10,000 rows, optimise: add an index on lower(full_name), and switch to incremental scanning (only check new records against existing).

remaining_study_months is stale (static value from import date) MEDIUM

student_enrichment.remaining_study_months

This field was calculated by the source organisation before the Excel was prepared and imported. It is NOT recalculated dynamically. A student who had "12 months remaining" at import time now has fewer. The fix: in report.py, recalculate dynamically from end_date - today rather than reading the stored value. The stored value should be treated as historical context only.

DEPLOYMENT.md is outdated LOW

DEPLOYMENT.md

Documents SQLite on Render.com and Streamlit Cloud. The project has migrated to Neon Postgres. Following DEPLOYMENT.md instructions will create a broken deployment. Use skills/devops.md instead.

Arabic name variants not caught by duplicate detection MEDIUM

app/duplicates.py:soft_sql

Soft duplicate detection uses exact lower(trim(full_name)) matching. "Mohamed" and "Muhammad" are the same person but different strings — not flagged. Arabic names with different Unicode normalisation (alef variants, teh marbuta) also don't match. See skills/arabic-translation.md for the normalise_arabic() implementation to add.
